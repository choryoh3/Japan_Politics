## 引き継ぎ事項
- 計画承認済み（確認事項への回答）: 最初の管理者はコマンドで付与。アカウント登録は誰でも可。出典 URL は任意（http(s):// で始まるものに限る）。収録範囲・照合値・契約から外した項目は planner 報告どおり。
- 実在データは公式サイトで確認して作る。Allowed domains に公式ホストが入るまで Sprint 1 に進まない。
- 「最新の内閣」は実装時点の公式情報で決める（契約は「終了日なしの内閣がちょうど 1 件」で確認する）。

### Sprint 1 からの引き継ぎ
- **データ**: 官邸サイト（全ページ404）と外務省（403）に到達できず、内閣・閣僚の実在データはすべて「知識のみ・未確認」。第1次・第2次高市内閣は特に不確実。出典 URL は官邸の URL パターンに沿って書いたもので、ページの実在は未確認（出典メモに明記済み）。公式資料との照合が必要。
- **ホスト**: 許可済みは www.kantei.go.jp / www.jimin.jp / www.mof.go.jp / www.mofa.go.jp。到達できるのは jimin.jp と mof.go.jp。
- **技術**: pnpm モノレポ（apps/web = Next.js 16、packages/db = Drizzle + libSQL）。`pnpm db:setup` で DB 作成・初期データ投入。人物は `persons.name` の一意制約のため、同姓同名は扱えない（Sprint 2 以降で見直し）。shadcn/ui と TanStack Query は未導入（必要になったスプリントで導入）。フォントは Noto Sans JP（next/font）。
- **evaluator の改善提案（任意）**: `:focus-visible` に `scroll-margin`（16px 程度）を足す。768px の一覧で第2次高市内閣の名前が隣のセルに 0.6px 食い込む。404 ページの説明文が語の途中で折れる。
- **デザイン**: 青い帯（#0070d1）の上のフォーカス枠は白（`.bg-primary` / `.on-primary` 配下）。帯の背景は `::before` の単一要素。`html, body` に `overflow-x: clip`。
- **運用**: evaluator はスクリーンショットを scratchpad の絶対パスに保存させること（リポジトリ内に画像を残さない）。

### Sprint 2 からの引き継ぎ
- **配色**: cookie（`jp-theme`）に保存し、ルート layout が `cookies()` で `<html data-theme>` をサーバー側で出す方式（インラインスクリプトは廃止。not-found ページでスクリプトが実行されない問題の根本対応）。全ページが動的描画。`ThemeToggle` は cookie と localStorage に保存し、マウント時に再適用する。
- **検索**: TanStack Query / shadcn/ui は未導入（`fetch` + `AbortController` + debounce 200ms）。よみがな検索はカタカナをひらがなに直して照合。人物は氏名・よみがな、内閣は内閣名の部分一致。LIKE の特殊文字はエスケープ、検索語は最大50文字（zod）。
- **evaluator の改善提案（任意）**:
  - `ThemeToggle` のマウント時、cookie と localStorage が食い違うとき localStorage が cookie を上書きする。cookie があれば cookie を優先し、無いときだけ localStorage を使う（generator、軽微）。
  - 「第2次岸田第2次改造内閣」が 768〜900px で「第2次岸田第2次 / 改造内閣」と折れる。`<wbr>` を「第2次岸田」と「第2次改造内閣」の間だけにする（designer）。
  - 「not-found で dark に切り替え → リロード → dark のまま」を自動で確かめるテスト（e2e 等）が未追加（単体は `parseTheme` のみ）。
  - 検索で、新しい問い合わせの読み込み中は前の候補が残り、↓ + Enter で古い候補を開けてしまう。
  - 契約外の検索の取りこぼし: 半角カタカナ（「ｲｼﾊﾞ」）と全角スペース区切り（「かとう　かつのぶ」）は 0 件。
- **データ**: Sprint 1 から変更なし（未確認の知識ベース。よみがなも seed の値で未確認）。
- **運用**: `pnpm build` が `apps/web/next-env.d.ts` を書き換えるので、ビルド後は `git checkout apps/web/next-env.d.ts` で戻す（コミットしない）。

### Sprint 3 からの引き継ぎ
- **認証**: Better Auth（メール + パスワード、8文字以上）。ユーザーの `role`（user/admin）。登録しても role は一般ユーザー（`input:false`）。管理者は `pnpm admin:grant <メール>` で付与（未登録は終了コード 2）。権限はセッションの role を毎回 DB から読む。`BETTER_AUTH_SECRET` は git 管理外の `apps/web/.env.local`（`openssl rand -base64 32` の出力。値は表示しない）。未設定の環境では `docs/project.md` の手順 4。
- **API**: `POST /api/persons`、`PUT/DELETE /api/persons/:id`（未ログイン 401、一般ユーザー 403、入力エラー 400、氏名重複 409、経歴ありの削除 409 `hasCareers`）。認証は `/api/auth/*`。
- **氏名の検証（許可リスト方式）**: `packages/db/src/person-input.ts`。NFC 正規化 → 連続する半角スペースを畳む → trim。許可: 文字・数字（見えない文字を除く）、RGI 絵文字（`\p{RGI_Emoji}`、v フラグ）、直前が文字・数字・結合文字の結合文字、区切り `・ · - ' ’ .`、空白は U+0020 と U+3000。見える文字が 0 なら `nameRequired`、許可外は `nameInvalidChar`、50 文字超は `nameTooLong`。メモは改行・タブ以外の制御文字・書式文字・見えない文字を拒否。人物フォームのページは `RGI_Emoji` の正規表現を使うので、Chrome 112+、Safari 17+、Firefox 116+ が前提。
- **仕様判断が要る点（planner / ユーザー）**: (1) 異体字セレクタ付きの氏名（IVS。例: 「葛󠄀城」）は拒否される。許可するか、許可するなら重複をどう扱うか。(2) NFC が変換する互換漢字（旧字体など）は正規の字形で保存される。(3) 混合スクリプトの見た目の類似（キリル文字の Ј と John の J、ローマ数字 Ⅰ と I、’ と '）は別の氏名として登録できる（UTS #39 の混同しやすい文字の制限をするか）。(4) 半角と全角の英数字、中黒と中点は別の氏名として扱う。(5) `&` `,` などを含む外国人名は入力できない。(6) 氏名に `%` `_` `\` は使えない（意図した仕様。検索側の LIKE の特殊文字のエスケープは別に有効）。
- **デザイン**: 黒ヘッダー → 青い章の帯 → キャンバス。ヘッダーの DOM 順は「ロゴ → 配色ボタン → アカウントナビ → 検索欄」（Tab 順と見た目の順は一致）。高さは 375px で 165px、768 / 1024px で 109px、1280px で 61px。フォーカス枠: 黒ヘッダー上は #53b1ff（白の要素もある）、青い帯の上は白、白キャンバスは #0064b7、黒キャンバスは #53b1ff。共通のフォームのクラスは `apps/web/src/lib/ui-classes.ts`。
- **承認待ち**: designer が DESIGN.md に無いダーク時の警告文字色 `warning-ink`（#ff6b86。黒地 7.7:1）を `globals.css` に追加した（DESIGN.md の warning #c81b3a は黒地 3.7:1 で文字には不足）。DESIGN.md への反映はユーザーの承認が必要。
- **evaluator の改善提案（任意）**: 320px でロゴが語の途中で折れる。表示名のサーバー側の長さ上限（Better Auth のフック）。削除ダイアログの初期フォーカスを「キャンセル」に。`ThemeToggle` は cookie 優先（localStorage は cookie が無いときだけ）。書き込み API の Origin 検査。`nameInvalidChar` の文言（「制御文字・改行・見えない文字など」）を、許可する記号が分かる文言に。
- **運用**: コンテナ再起動で Designer の最終報告が失われることがあった。サブエージェントには「作業の最後に必ず最終報告を書く」よう指示する。評価は使い捨て DB（`DATABASE_URL=file:<scratchpad>/...`）で書き込みを伴う確認をし、`local.db` は読み取りのみ。Sprint 4 以降の評価でも同様。

### Sprint 4 からの引き継ぎ（条件付き合格。ユーザー判断）
- **経緯**: Sprint 4 の評価は試行 1〜5 のすべてで、契約 15 項目・権限（401 / 403 / Origin 検査）・入力検証・Sprint 1〜3 の回帰が合格。不合格は毎回「見た目のクラフト 6/10（基準 7）」のみで、直すたびに別の画面・別の極端な入力で同じ種類の折れ・はみ出しが見つかった。ユーザーは「今の状態で条件付き合格として Sprint 5 へ進む」と判断した。**`docs/sprints/sprint-4-eval.md` の最新判定は FAIL のまま（evaluator の判定は覆していない）。`python3 scripts/validate_docs.py --verdict 4` は FAIL を返す。Sprint 5 の事前確認でこれが出るが、ユーザー判断により進める。**
- **Sprint 5 の冒頭で直す 2 点（Sprint 5 の generator / designer に最初の作業として渡す。契約の項目ではなく、持ち越しの条件）**:
  1. **人物ページ `/persons/N` の役職の列**（`apps/web/src/app/persons/[id]/page.tsx`）: 役職名が「内閣総理大／臣」のように 1 文字だけ次の行に落ちる（初期データ。768〜1440px。59 ページ）。原因は役職の列が `w-[15%]` で `text-lg`（18px）、768px で 6 文字の役職名に約 108px 必要なのに 101px しかないこと。直し方の案: 役職の `<td>` に `md:max-lg:text-base` と `[text-wrap:pretty]`、または列を 15%→18% 前後に広げて他の列で調整。**所属の列（試行 4 の修正点: `md:max-lg:text-sm`、所属 22% / 出典 23%）を再び狭めないこと。**
  2. **英字だけ（空白なし）の 50 文字の氏名**が、閣僚名簿と内閣一覧のセルからはみ出して隣の列に重なる: 名簿（`apps/web/src/app/cabinets/[id]/page.tsx` の氏名の `<Link className="link-inline inline-flex min-h-11 items-center">`）は氏名を `<span className="min-w-0 [overflow-wrap:anywhere]">` で包み Link に `max-w-full`、一覧（`apps/web/src/app/page.tsx` の総理大臣の `<td>`）に `[overflow-wrap:anywhere]`。**`anywhere` が普通の氏名（「林芳正」）を折らないことを、全幅・初期データ全件の走査で確かめる**（試行 4 の「内／閣」の再発を避ける）。
- **評価の基準の線引き（Sprint 5 以降の evaluator への指示に入れる）**: 見た目の不合格は、「契約・初期データ・現実的な入力（実在の内閣名・氏名・役職名・日付の最長のもの）で再現できる欠陥」に限る。極端な入力（空白のない 50 文字の英字、など）で見つかったものは、改善提案として記録し、FAIL の理由にしない。
- **その他の改善提案（任意）**: 人物欄（`role="combobox"`）で ↓ / Enter が候補に効かない（ヘッダーの検索欄は効く）。選択・登録・削除のあとフォーカスが `body` に落ちる。削除ダイアログの初期フォーカスを「キャンセル」に。発足日 `0000-01-01` が通る（下限を設ける）。ルートの not-found が英語の既定の文言（日本語の `not-found.tsx` を）。出典メモが 904〜1232px で段落の右端を 0.6〜6px 越える（セルの余白内。他の列とは重ならない）。内閣一覧で総理がいない内閣のセルが空（「—」の表示）。削除済みの人事の編集 URL が「内閣が見つかりません」と出る（「人事が見つかりません」に）。
- **仕様判断が要る点（planner / ユーザー）**: 重なりを許す役職は特命担当の 3 役職（行政改革担当大臣・経済安全保障担当大臣・少子化対策担当大臣）。`docs/spec.md` は「特命担当の国務大臣は重複を許す」としか書いておらず、generator の判断。終了日なしの内閣を追加すると「現在の内閣」が複数になる。同じ人物が同じ内閣の同じ役職に 2 回就く記録（退任後の再任）は `appointmentDuplicate` で拒否される。人事の就任日が空欄のときは「内閣の発足日から」として扱う。
- **技術**: 管理者の閣僚名簿は 1024px 以上で表、それ未満はカード（375px と同じ）。一般・未ログインは 768px から表。書き込み API は共通の Origin 検査（`apps/web/src/lib/origin-guard.ts`。`/api/*` 全体。外部 Origin の変更系を 403、同一 Origin と Origin なしの curl は通す。Hono 標準の `csrf` は JSON の変更系を検査せず DELETE を誤って 403 にしたため自前）。`ThemeToggle` は cookie 優先（Sprint 3 の提案に対応済み）。内閣名・出典 URL・出典メモの検証は `packages/db/src/cabinet-input.ts`（許可リスト方式）、期間・重なりは `tenure.ts`、役職一覧は `cabinet-posts.ts`。
- **運用**: `pnpm build` と dev サーバーは `apps/web/next-env.d.ts` を書き換える（`.next/types` 版と `.next/dev/types` 版が切り替わる）。終了前に `git status` で確認し、`git checkout apps/web/next-env.d.ts` で戻してからコミットする。走査スクリプトは scratchpad の `t3/`、`t4/`、`t5/`（セッションが変わると消える）。
